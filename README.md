# PicoRV32 RISC-V System-on-Chip (SoC)

A complete 32-bit RISC-V (RV32I) System-on-Chip designed in Verilog around the [PicoRV32](https://github.com/YosysHQ/picorv32) CPU core, equipped with custom memory-mapped peripherals, verified with bare-metal C and Assembly firmware in simulation, with an experimental port of the Zephyr RTOS.

---

## Overview

This project implements a fully functional, self-contained RISC-V computer in Verilog (tested with Icarus Verilog). The CPU executes real RISC-V machine code generated by the GNU GCC toolchain (`riscv64-zephyr-elf-gcc`), accessing memory and custom memory-mapped peripherals over PicoRV32's native bus.

### Key Highlights
- **CPU Core**: PicoRV32 (RV32I base integer instruction set, unmodified, 32 registers).
- **Memory**: 8 KB single-cycle synchronous RAM with 4-byte strobe write enables.
- **Peripherals**:
  - **UART TX**: 8N1 serial transmitter with internal baud divider and status register.
  - **GPIO**: 8-bit output register with read-back capability.
  - **Timer**: 32-bit free-running cycle counter (readable and reloadable).
- **Bus Architecture**: PicoRV32 native memory interface (`mem_valid` / `mem_ready` handshake, single-cycle response). *Note: This bus is PicoRV32 native, not AXI.*
- **Firmware Support**: Bare-metal Assembly (`test.S`, `uart_test.S`) and C firmware (`main.c`, `main_gpio.c`, `main_timer.c`, `custom_app.c`) with custom runtime startup (`crt0.s`) and linker script (`c_test.ld`).
- **Comprehensive Verification**: 6 regression testbenches + an interactive simulation monitor that decodes serial UART transmissions and pin toggles directly to the terminal.

## System Architecture

```
                       +----------------------------------+
                       |           PicoRV32 CPU           |
                       |       (RV32I, Reset: 0x0)        |
                       +----------------------------------+
                                        |  PicoRV32 Native Bus
                                        |  (valid / ready handshake)
                                        v
                    +----------------------------------------+
                    |        picorv32_addr_decoder           |
                    |         (mem_addr[31:28])              |
                    +----------------------------------------+
                        |            |            |           |
             0x0        |  0x1       |  0x2       |  0x3      |
        +---------------+  +---------+  +---------+  +--------+
        |                  |            |            |
        v                  v            v            v
+---------------+  +------------+  +---------+  +-----------+
| 8 KB RAM      |  | UART TX    |  | GPIO    |  | Timer     |
| (2048 x 32b)  |  | (8N1 serial|  | (8-bit  |  | (32-bit   |
| byte strobes  |  |  + status) |  |  output)|  |  counter) |
+---------------+  +------------+  +---------+  +-----------+
```

### Memory Map

| Peripheral | Base Address Range | Register / Offset | Description |
|---|---|---|---|
| **RAM** | `0x0000_0000 - 0x0000_1FFF` | `+0x0000` to `+0x1FFC` | 8 KB primary memory (Code, Data, Stack) |
| **UART TX** | `0x1000_0000 - 0x1000_00FF` | `+0x0` (`TX_DATA`) | Write 8-bit character to transmit |
| | | `+0x4` (`TX_STATUS`) | Bit 0: `tx_ready` (1 = idle, 0 = transmitting) |
| **GPIO** | `0x2000_0000 - 0x2000_00FF` | `+0x0` (`GPIO_DATA`) | Bits [7:0] drive output pins; read returns state |
| **Timer** | `0x3000_0000 - 0x3000_00FF` | `+0x0` (`TIMER_COUNT`)| 32-bit counter (increments every clock cycle) |

### CPU Configuration (`picorv32_top.v`)
- `PROGADDR_RESET = 32'h0000_0000` (Execution starts at 0x0 in RAM)
- `STACKADDR = 32'h0000_1FFC` (Top of 8 KB RAM; auto-loaded into `sp` at reset)
- `ENABLE_IRQ = 0` (Interrupts disabled; custom IRQ instruction disabled)
- `ENABLE_PCPI = 0` (Co-processor interface disabled)

## Verification & Testing

The SoC includes an automated test suite verifying each module independently.

### 1. Regression Test Suite
Run all 6 hardware testbenches in sequence:

```bash
bash run_tests.sh
```

**Results:**
| Testbench | What it Tests | Result |
|---|---|---|
| `picorv32_top_tb.v` | Zero-initialized RAM causes illegal instruction trap at 175 ns | **PASS** |
| `picorv32_program_tb.v` | CPU boots assembly, writes `0xCAFEBABE` to `0x100` | **PASS** |
| `picorv32_uart_tb.v` | UART FSM transmits `0x41` ('A') with correct 8N1 timing | **PASS** |
| `picorv32_c_test_tb.v` | C program (`main.c`) transmits `"Hi"` over UART | **PASS** |
| `picorv32_gpio_tb.v` | C program (`main_gpio.c`) writes `0xAA` to GPIO pins | **PASS** |
| `picorv32_timer_tb.v` | C program (`main_timer.c`) reads timer before and after delay | **PASS** |

### 2. Interactive C Application Demo
Run the interactive firmware demo (`fw/custom_app.c`):

```bash
bash run_custom.sh
```

This compiles the C code, links it, generates the hex image, and runs `tb/picorv32_print_tb.v`, which actively samples the UART serial line and monitors the GPIO pins:

## Zephyr RTOS Port Status: Work in Progress

An objective of this project was to boot the [Zephyr RTOS](https://www.zephyrproject.org/) on this custom hardware.

### What Was Accomplished:
- Implemented Zephyr SoC tree at `zephyr-app/soc/riscv/picorv32_soc`.
- Implemented custom board target at `zephyr-app/boards/others/picorv32_board`.
- Wrote Devicetree (`picorv32_board.dts`) and bindings for memory and UART.
- Configured Kconfig options (`CONFIG_SOC_PICORV32`, `CONFIG_SYS_CLOCK_EXISTS=n`).
- Successfully passed Devicetree preprocessing and Kconfig validation.

### Hardware Blocker (The CSR Gap):
During kernel compilation, the GNU assembler rejected Zephyr's context-switch and interrupt-lock code:
```text
Error: instruction csrs requires extension 'zicsr'
Error: instruction csrrc requires extension 'zicsr'
```

**Root Cause:**
Zephyr's RISC-V architecture layer unconditionally requires privileged Control and Status Registers (`mstatus`, `mtvec`, `mepc`, `mcause`, `mscratch`) and the `Zicsr` instruction set (`csrrw`, `csrrs`, `csrrc`). 

PicoRV32 was intentionally designed as a minimal, compact RV32I core without privileged CSRs. It implements custom, non-standard instructions (`maskirq` with opcode `0001011`) rather than the RISC-V Privileged Architecture. 

This is documented extensively with resolution options in:
- [`docs/REPORT.md`](docs/REPORT.md) (Section 6 & 8)
- [`docs/STAGE6_DETAILS.md`](docs/STAGE6_DETAILS.md)

## Prerequisites & Toolchain

To simulate the design and compile the firmware locally:

1. **Hardware Simulation**:
   - `iverilog` (Icarus Verilog 11.0+)
   - `vvp` (Icarus Verilog simulation engine)
2. **Firmware Toolchain**:
   - `riscv64-zephyr-elf-gcc` (from [Zephyr SDK](https://github.com/zephyrproject-rtos/sdk-ng) 1.0.1+ or standard `riscv32-unknown-elf-gcc`)
   - `python3` (for `bin2hex.py`)
